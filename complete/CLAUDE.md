## What this is

This is the `complete` reference solution for the Spring "Getting Started" guide
*gs-crud-with-vaadin* — a small Spring Boot + Vaadin Flow app demonstrating full CRUD
(Create, Read, Update, Delete) over a Spring Data JPA repository, plus a filtered search
example. The repo root (one level up) also contains an `initial/` project, which is the
same app before the Vaadin UI/editor pieces are added — useful for diffing "before" vs
"after" when following the guide.

Maven is the build tool used for this project.

## Common commands

Run from this directory (`complete/`):

```bash
# Run the app (serves at http://localhost:8080)
./mvnw spring-boot:run

# Build
./mvnw package

# Run all tests
./mvnw test

# Run a single test class
./mvnw test -Dtest=CustomerEditorTests

# Run a single test method
./mvnw test -Dtest=MainViewTests#shouldFilterOutTheGridWithTheProvidedLastName
```

Java 21 toolchain is required (configured in `pom.xml`).

## Architecture

All application code lives in `src/main/java/com/example/crudwithvaadin/`:

- **`Customer`** — JPA `@Entity` (id, firstName, lastName). Has a no-arg protected
  constructor (required by JPA) plus a convenience `(firstName, lastName)` constructor.
- **`CustomerRepository`** — Spring Data `JpaRepository<Customer, Long>`. Adds one
  declarative query method, `findByLastNameStartsWithIgnoreCase`, used for the filter
  feature — no manual query implementation needed.
- **`CustomerEditor`** — a `@SpringComponent @UIScope` Vaadin form component (one instance
  per UI session). Owns the edit/save/delete UX for a single `Customer`: it binds form
  fields to a `Customer` bean via Vaadin `Binder`, and directly calls
  `CustomerRepository.save()`/`.delete()`. It notifies interested parties (currently only
  `MainView`) of completed edits through a `ChangeHandler` callback interface set via
  `setChangeHandler()` — this is the only coupling between the editor and its container,
  keeping the editor reusable in other views.
- **`MainView`** — `@Route`-annotated top-level Vaadin view (the app's root page). Wires
  together a `Grid<Customer>`, a filter `TextField`, an "add new" `Button`, and an injected
  `CustomerEditor`. Selecting a grid row opens that customer in the editor; the "New
  customer" button opens the editor with a blank `Customer`. `listCustomers(filterText)`
  is the single place that decides between `repo.findAll()` and the filtered repository
  query.
- **`CrudWithVaadinApplication`** — Spring Boot entry point. Its `CommandLineRunner` bean
  seeds five sample customers on every startup and logs some example repository queries —
  this is demo seed data, not persisted fixtures.

Data flows one way through the UI: `MainView` renders repository data into the `Grid`;
selecting a row or clicking "New customer" hands a `Customer` to `CustomerEditor`; the
editor talks directly to `CustomerRepository` for persistence and then calls back into
`MainView` (via `ChangeHandler`) to refresh the grid. There is no separate service/DTO
layer — components talk to the JPA repository directly, matching the tutorial's scope.

Persistence is an in-memory H2 database (auto-configured via `spring-boot-h2console` and
the H2 runtime dependency) — nothing persists across restarts, and no
`application.properties` overrides are present.

## Testing approach

- `CustomerEditorTests` uses plain Mockito (`@ExtendWith(MockitoExtension.class)`,
  `@Mock`/`@InjectMocks`) to unit-test `CustomerEditor` save/delete logic against a mocked
  `CustomerRepository`, without booting Spring.
- `MainViewTests` boots a narrow Spring context (`@SpringBootTest(classes =
  MainViewTests.Config.class)`) that excludes Vaadin's own auto-configuration
  (`SpringBootAutoConfiguration`) and wires only the JPA repository plus a hand-rolled
  `Config` inner class that seeds test data. `MainView`/`CustomerEditor` are then
  constructed manually in `@BeforeEach` rather than injected, since the Vaadin UI
  scaffolding isn't running.
- `src/main/frontend/generated/` is Vaadin's build output (dev-mode bootstrap files,
  connectors, etc.) — do not hand-edit it; it is regenerated by the Vaadin
  Maven plugin.
